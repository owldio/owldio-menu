# 《月光下的約定》樂曲解說：軟翻頁與連續封面

- 日期：2026-09-21
- 路由：`/moonlight-promise`（不變）
- 延伸自：[2026-09-18-moonlight-notes-book-design.md](2026-09-18-moonlight-notes-book-design.md)

## 背景

委託人看過 [Visual Paradigm 的電子節目冊](https://online.visual-paradigm.com/tw/community/book/250615--2c0jlltrzf)，指名要那種翻書感，並指出現行封面的表現方式不對。

兩件事，各有一個明確的現況問題。

**翻頁不是翻書。** 現行做法把 48 頁絕對定位排成一條橫帶，翻頁只是整條帶的 `translate3d` 平移（`notes-book.js` 的 `layoutPages`、`notes-geometry.js` 的 `pageOffset`）。中間影格看起來是輪播，不是書。參考站用的是 `turn.js`：書角斜斜掀起、露出彎曲的頁背三角形、帶柔影，下一頁從底下透出來。

**封面讀起來是「後面多了一層背景」，不是延續。** 畫面上實際有三層：舞台底（`.view--notes-book::before` 自己的深色與豎琴線）、書頁（`cover-moonlight-promise.webp`，中間約 1064 px 是印刷面板，左右是前兩輪直接畫進圖檔的深藍色帶）、以及面板本身。頁面只有 511×768（跨頁的一半），`object-fit: cover` 再裁掉一部分色帶，於是留下一道垂直接縫，接縫外是死掉的平色。

前兩輪（`5019011`、`6b15403`）試圖用改圖檔解決 —— 手繪把面板往外延伸。方向錯了：手繪延伸永遠會在接縫處露餡。委託人另外提供的橫式主視覺（1672×941）證明設計師本來就有一版寬幅構圖，不需要假造。

## 目標

1. 翻頁是真的軟翻頁：書角掀起、頁背可見、陰影正確、可以抓著書角跟手拖。
2. 封面的畫在畫面上是連續的：沒有色帶、沒有接縫、沒有第三層背景。
3. 不犧牲既有的閱讀能力：文字仍是活的 HTML、可選取、依字級重新分頁、可捏合縮放至 4×。

## 非目標

- 不動 `/sense-and-sensibility` 的 PDF 閱讀器。
- 不安裝 `page-flip` 套件（只移植其幾何，見下）。
- 不做書脊厚度、頁緣堆疊那類擬真裝飾 —— 會把注意力從內容拉走。
- 不做翻頁音效。

## 推翻先前的決定

前一份 spec 第 222 行寫：

> 不做 3D `rotateY` —— 在低對比的深色頁面上，翻轉的中間影格讀起來只是閃爍。

這次推翻它。但那個顧慮是真的，必須正面解掉，不能只是忽略。

參考站的頁面是亮的，摺痕靠頁面自身的明度差就看得出來；我們的頁面是深藍夜色，同樣的翻轉只會是一團深色在動。解法不是把頁背改成象牙白（那在這片夜色裡是異物），而是：

- 頁背同樣是夜色。
- **摺線上一道金色亮邊**把摺痕立起來。金線本來就是印刷節目單的語彙，不是憑空加的裝飾。
- **三層陰影**：翻動頁內側、翻動頁外側、翻動頁投在底頁上的。

先前 spec 的該段落一併改寫，記錄新結論與理由。

## 方案選擇

評估過三條路。

**整包裝 `page-flip`（StPageFlip 2.0.7，MIT）。** HTML 模式用 `clip-path: polygon()` 加 `rotate` 直接對活的 DOM 做軟翻頁，文字仍可選取；支援 `data-density="hard"`、`showCover`、直式／跨頁自動切換。但它要接管容器尺寸、指標事件與跨頁判斷，而這本書最特別的三件事正好都在那裡：頁等於整個螢幕、依字級重新分頁、可捏合縮放至 4×。它的 `Render.convertToBook()` 以未經 `scale()` 的座標系換算，縮放狀態下摺頁幾何會歪。等於拿一個為固定尺寸圖片書設計的套件去撞我們已經寫好也已經測過的部分。

**完全自己寫。** 控制力滿分，但摺頁數學是這題真正難的部分，自己推容易在邊界角度出錯。

**只移植數學，介面自己接。** 採用這條。

理由：難的部分（摺頁幾何）用驗證過的實作；容易撞的部分（尺寸、手勢、縮放、重排）留在自己手上。移植後的模組是純函式，和既有的 `notes-geometry.js`、`reader-gestures.js` 同一個寫法，可以直接測。

## 摺頁幾何

把 StPageFlip 的 `FlipCalculation`（MIT，433 行）移植為 `src/domain/page-fold.js`。它只依賴一個線段交點工具，沒有 DOM、沒有時間、沒有狀態。

構造是標準的：**摺線是書角與指標連線的垂直平分線**，再與頁面四邊求交點，得到翻動頁與底頁的裁切多邊形。

```js
foldFrom({ corner, pointer, pageWidth, pageHeight })
// → { flippingClip, bottomClip, angle, position, shadow, progress }
```

| 欄位 | 內容 |
| --- | --- |
| `flippingClip` | 翻動頁的裁切多邊形頂點 |
| `bottomClip` | 底頁的裁切多邊形頂點 |
| `angle` | 翻動頁的旋轉角（弧度） |
| `position` | 翻動頁的位移 |
| `shadow` | 陰影起點與角度 |
| `progress` | 0 至 1，供判定與 reduced-motion 用 |

授權：MIT，於 `README.md` 的第三方段落標註來源與原作者。

## 封面

### 模型

跨頁時封面是**兩張硬頁**，各承載橫式主視覺的左半與右半。圖在畫面上連續，中間只有一道書溝細線 —— 那是對的，它是一本書。

翻第一頁時，右半頁整片繞書脊旋轉過去蓋到左半上，露出目錄跨頁；它的背面是內封，純夜色無字。硬頁不做書角掀起（硬卡紙不會捲），只做繞脊旋轉。

手機單頁時封面是一張直式滿版硬頁。

### 素材

| 情境 | 素材 | 呈現 |
| --- | --- | --- |
| 桌機跨頁 | 橫式主視覺 1672×941 | 左右兩張硬頁各承載左半／右半 |
| 手機單頁 | `cbdc5d5` 版的 960×2028 乾淨印刷面板 | 滿版 |
| 兩者的頁背 | 無素材 | 純夜色內封 |

`cbdc5d5:assets/cover-moonlight-promise.webp` 是 960×2028，還沒被畫上色帶，從 git 取回即可。

現行 1558×2022 那張（左右畫了色帶的）退役。

**外部依賴：** 兩張素材解析度都偏低 —— 橫式 1672 寬用於跨頁滿版，在 2560 寬的螢幕上會糊；直式 960 寬在 3× DPR 手機上略低於所需。先用現有的做，同時向設計師索取原始檔（PSD／AI，或至少 3840 寬的輸出）。換檔只是替換 asset，不影響其他設計。這是唯一會擋住成品品質的外部依賴。

### 跨頁配對

封面原子標上 `spansSpread: true`。`notes-pagination.js` 在跨頁時把它排成兩頁（左半、右半），單頁時仍是一頁 —— 這是 `FULL_PAGE_KINDS` 既有處理的延伸。

`buildSpreads(total, twoUp)` 現在是「第 0 頁獨佔，其後兩兩配對」。封面佔滿一個跨頁後改為依序配對 `[[0,1],[2,3],…]`，內容從第 2 頁起，配對關係與現在一致。

尾頁（贊助商頁）若落在跨頁的左半，右半留空為純夜色 —— 與現行單頁尾頁的處理相同，不特別補頁。

單頁時全部不變，每頁自成一個跨頁。

## 互動

| 動作 | 行為 |
| --- | --- |
| 觸控／筆按住書角拖 | 摺頁跟手，放開依 `resolveSwipe` 判定翻過去或彈回 |
| 點右側 30% | 從右下角自動摺過去，完整動畫 |
| 點左側 30% | 反向 |
| 點中間 | 選單（沿用 `tapZone`） |
| 滑鼠拖曳 | 仍留給選取文字（前一份 spec 第 148 行的既有決定） |
| 滑鼠懸停書角 | 露出一小片翹角，桌機的可發現性 |
| 縮放後（zoom > 1） | 不翻頁，只平移 |
| 跳頁（目錄／縮圖／捲軸／深層連結） | 維持淡入，只有相鄰頁才摺 |
| `prefers-reduced-motion` | 摺頁改為淡入淡出 |

「縮放時不翻頁」是既有規則，這裡順帶解掉了整包裝套件那條路的致命傷：`scale()` 下摺頁座標會歪 —— 我們根本不在那個狀態下摺。

## 效能

全部頁面常駐 DOM 不變（1024×768 實測 48 頁，頁數隨螢幕與字級變動），`data-near` 仍只讓相鄰頁 `will-change`。

摺頁時只有一張葉片在動。**背面副本在翻動開始時 clone、翻動結束即丟**，不常駐 48 份。

翻動中對該葉片關掉 `box-shadow`，陰影改由 fold 模組自己畫 —— 避免 `clip-path` 每幀更新時與 `box-shadow` 一起重繪。

## 測試

`tests/page-fold.test.js`：

- 角度隨指標移動單調變化。
- 裁切多邊形的頂點數在各象限都正確。
- `progress` 從 0 走到 1。
- 邊界：指標壓在書角上、指標越過對邊、指標跑到頁外。

擴充既有測試：

- `notes-pagination.test.js`：封面在跨頁時排成兩頁、單頁時仍是一頁；配對結果與尾頁落在左半的情形。
- `reader-gestures.test.js`：抓角判定（上緣／下緣、左／右、不在角上）。

既有測試全部維持綠燈，尤其是分頁引擎的內容守恆不變式。

手動驗證：桌機跨頁、手機單頁、縮放後不翻頁、`prefers-reduced-motion`。320 / 375 / 768 / 1024 / 1440 寬度截圖。

## 分期

1. `page-fold.js` 純幾何加測試。
2. **單一葉片可摺的原型，截圖確認質感。**
3. 接上全書：手勢、跳頁、reduced-motion。
4. 封面素材與跨頁配對。
5. 清掉滑動帶的舊碼與樣式，改寫前一份 spec 的 3D 決定。

## 風險

- **深色軟翻頁可能就是不好看。** 當初否決 3D 不是沒道理。因此第 2 階段設為檢查點：先做出單一葉片、截圖確認，再接上全書。若到那時質感不成立，掉頭的成本只有一個模組。
- **素材解析度。** 橫式 1672 寬、直式 960 寬都偏低。需要設計師的原始檔，否則跨頁滿版封面在大螢幕上會糊。這是外部依賴，不在程式碼裡。
- **手機每幀更新 `clip-path` 的成本。** StPageFlip 以同樣做法運行於行動裝置，風險可控，但仍需在真機上驗證；必要時翻動中降低陰影層數。
- **移植正確性。** 摺頁幾何的邊界條件多。以單元測試涵蓋各象限與越界情形，而非只測正常路徑。
